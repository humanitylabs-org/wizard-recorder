# Failed Start and shared capture recovery

Recorder owns its update hold. Shared shell storage does not prove that the app has no private audio or queued uploads.

- Acquire the hold before Start. A late rejected Start may already own a session, capture ID, result, sent/final sequence or uploader work; keep that exact engine and never cancel/ack it to free Reload.
- Clear a failed controller only after positive empty own-memory plus app-scoped `capture.current()` / `capture.pending()` proof. Recheck controller identity both inside the proof and at its callers after the await. Two same-task Start or Start+Stop continuations must not detach a newer starting engine or release its hold.
- The shell can retain a capture when the app's Start reply/setup fails. Retry/Stop on an empty error controller reuses the existing reattach path, adopting the exact app-scoped capture ID. Read positive `current()` before fetching `pending()`; the shell deliberately rejects an empty pending result when an own active/recovery-live row exists. After awaiting pending, recheck controller identity and current capture. Hold/observers remain owned through adoption. Never start a second microphone to recover it. Stop proceeds through the normal verified save/ack path only if the adopted meeting matches the failed controller's meeting; a different meeting is shown instead and requires its own explicit Stop. Already-pending recovery uploads are unchanged.
- `SharedMeeting.start` always sends `meta.meetingId`. Shell `current` and `pending` are bound by app-services to the verified frame's app ID; `resumeId` rebinds an existing active session rather than starting another engine. Legacy metadata without a meeting link can use only the persisted `mizel.sharedCapture` hint whose capture ID exactly matches. A missing/mismatched link remains retained with an explicit error, never attached to the currently viewed meeting by guesswork.
- Reattachment checks controller identity after asynchronous start/drain/stop/ack. A stale continuation cannot change or tear down its replacement. No global hold release on durable rows.
- Warm input moves synchronously from the preparations map into the shell session before Start awaits. `discardPrepared` checks that map and is a no-op after consumption; the late app catch cannot close the retained session's consumed input.

`test-recording-start.mjs` executes production controller functions with synthetic dependencies. It covers same-task double Start and Start+Stop, late retained custody, exact-ID adoption for Retry and Stop, concurrent adoption, verified legacy hints, and retained/unknown standalone unload protection. The companion shell regression file tests consumed warm input, unknown native truth without starving safe browser-row repair, final native truth refresh, and non-destructive reload preparation.

These are source candidates, not proof that an already loaded handset has new JavaScript. Never clear browser storage, force-stop a capture, or bypass an unknown in-memory buffer to bootstrap Reload.
